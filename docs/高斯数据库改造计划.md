# 高斯数据库改造计划

> 目标：把当前基于 MySQL 8.0 的图书管理系统迁移到高斯数据库（GaussDB / openGauss，PostgreSQL 兼容）。
> 读者：负责数据库改造的后端同学。
> 原则：**先保留 MySQL 可回滚，再新增 Gauss 配置；不要直接改 main 上的 MySQL 配置。**

## 0. 先确认目标数据库

“高斯数据库”有不同形态，SQL 兼容性不完全一样：

| 形态 | 说明 | 本计划适用性 |
| --- | --- | --- |
| GaussDB（华为云） | PostgreSQL 兼容 | 适用，按 PostgreSQL 语法 |
| GaussDB(DWS) | 数据仓库版本，部分语法不同 | 需先确认版本和 JDBC 驱动 |
| openGauss | 开源 PostgreSQL 系 | 适用，按 PostgreSQL 语法 |

**开工前必须先确认：**

- 老师要求的是哪一种高斯？版本号是多少？
- 能否创建 schema、sequence、trigger、function？
- 是否允许使用 `gsql` / `gs_dump` / `gs_restore` 或 `psql` / `pg_dump`？
- JDBC 驱动用哪个：现有 `pom.xml` 里的 `huaweicloud-dws-jdbc`，还是标准 `org.postgresql:postgresql`？

在没确认之前，不要直接改现有 MySQL 数据源。

## 1. 当前代码中的 MySQL 依赖清单

| --- | --- | --- |

| `book-java/src/main/resources/application-gauss.yml` | 现有 Gauss 连接配置 | 更新地址、schema、驱动 |
| `book-java/src/main/resources/application-mysql.yml` | MySQL 连接 | 保留，作为回滚配置 |
| `book-java/book-mysql.sql` | MySQL DDL / 自增 / 触发器 | 转换为 Gauss DDL，生成新的 `book-gauss.sql` |
| `book-java/book-gauss.sql`、`database.sql` | 旧版高斯脚本 | 只作参考，不能直接执行，需要按当前表结构重写 |

| `pom.xml` | MySQL 驱动 + 华为 DWS 驱动 | 确认 Gauss 驱动；必要时增加 `org.postgresql:postgresql` |

当前业务代码里没有手写 `ON DUPLICATE KEY`、`INSERT IGNORE`、`LIMIT offset,count` 等运行时 SQL（种子脚本除外），主要改造集中在：

1. 分页方言
2. 数据大屏聚合 SQL
3. 备份/恢复工具
4. 建表脚本与触发器

## 2. 目标表结构

当前 MySQL 共有 11 张表：

- 业务表：`book`、`book_detail`、`borrow_info`、`u_user`、`r_role`、`user_role`、`privilege`、`role_privilege`、`user_log`
- 会话表：`SPRING_SESSION`、`SPRING_SESSION_ATTRIBUTES`

ER 关系不变，仍然是这些表；改造的是字段类型、自增方式、SQL 语法和触发器。

### 2.1 MySQL → GaussDB 类型映射

| MySQL | GaussDB / PostgreSQL | 备注 |
| --- | --- | --- |
| `INT AUTO_INCREMENT` | `SERIAL` 或 `GENERATED BY DEFAULT AS IDENTITY` | 二选一，项目统一 |
| `BIGINT` | `BIGINT` | 不变 |
| `TINYINT` / `TINYINT(1)` | `SMALLINT` | 不要用 `BOOLEAN` 存 0/1，避免 MyBatis 映射差异 |
| `DATETIME` | `TIMESTAMP` | 建议 `TIMESTAMP WITHOUT TIME ZONE` |
| `VARCHAR(n)` | `VARCHAR(n)` | 不变 |
| `TEXT` / `LONGTEXT` | `TEXT` | 不变 |
| `BLOB` | `BYTEA` | 会话属性必须用 `BYTEA` |
| `ENGINE=InnoDB` / `CHARSET` | 删除 | Gauss 不支持 MySQL 表选项 |
| 反引号 `` ` `` | 去掉或使用双引号 | 不要保留 MySQL 反引号 |
| `ON UPDATE CURRENT_TIMESTAMP` | 触发器 | 当前业务表基本未用；如新增字段要注意 |
| `LIMIT offset,count` | `LIMIT count OFFSET offset` | 旧 `database.sql` 里的写法要改 |

### 2.2 建表示例

```sql
CREATE SCHEMA IF NOT EXISTS digital_book;
SET search_path TO digital_book;

CREATE TABLE book (
    book_id     SERIAL PRIMARY KEY,
    book_name   VARCHAR(50) NOT NULL,
    book_author VARCHAR(50) NOT NULL,
    isbn        VARCHAR(20) NOT NULL,
    stock       INT NOT NULL
);

CREATE TABLE book_detail (
    book_id      INT PRIMARY KEY REFERENCES book(book_id) ON DELETE CASCADE,
    book_name    VARCHAR(50) NOT NULL,
    book_author  VARCHAR(50) NOT NULL,
    publisher    VARCHAR(50) NOT NULL,
    time         VARCHAR(10) NOT NULL,
    image        VARCHAR(100),
    introduction TEXT
);

CREATE TABLE u_user (
    user_id   SERIAL PRIMARY KEY,
    user_name VARCHAR(50) UNIQUE,
    password  VARCHAR(100),
    age       INT,
    sex       VARCHAR(5),
    phone     VARCHAR(30)
);

CREATE TABLE r_role (
    role_id   SMALLINT PRIMARY KEY,
    role_name VARCHAR(50)
);

CREATE TABLE privilege (
    privilege_id   SMALLINT PRIMARY KEY,
    privilege_name VARCHAR(50)
);

CREATE TABLE user_role (
    id      SERIAL PRIMARY KEY,
    user_id INT NOT NULL REFERENCES u_user(user_id) ON DELETE CASCADE,
    role_id SMALLINT NOT NULL REFERENCES r_role(role_id),
    UNIQUE (user_id)
);

CREATE TABLE role_privilege (
    id           SERIAL PRIMARY KEY,
    role_id      SMALLINT NOT NULL REFERENCES r_role(role_id),
    privilege_id SMALLINT NOT NULL REFERENCES privilege(privilege_id),
    UNIQUE (role_id, privilege_id)
);

CREATE TABLE borrow_info (
    user_id     INT NOT NULL REFERENCES u_user(user_id),
    user_name   VARCHAR(50) NOT NULL,
    book_id     INT NOT NULL REFERENCES book(book_id),
    book_name   VARCHAR(50) NOT NULL,
    borrow_time BIGINT NOT NULL,
    deadline    BIGINT NOT NULL,
    PRIMARY KEY (book_id, user_id)
);

CREATE TABLE user_log (
    log_id      BIGSERIAL PRIMARY KEY,
    user_id     INT,
    role_id     SMALLINT,
    action_time TIMESTAMP,
    action_type SMALLINT,
    description VARCHAR(200),
    user_name   VARCHAR(50),
    role_name   VARCHAR(50)
);
```

会话表建议直接使用 Spring Session 官方 PostgreSQL 脚本，核心字段：

```sql
CREATE TABLE spring_session (
    primary_id            CHAR(36) NOT NULL PRIMARY KEY,
    session_id            CHAR(36) NOT NULL UNIQUE,
    creation_time         BIGINT NOT NULL,
    last_access_time      BIGINT NOT NULL,
    max_inactive_interval INT NOT NULL,
    expiry_time           BIGINT NOT NULL,
    principal_name        VARCHAR(100)
);

CREATE TABLE spring_session_attributes (
    session_primary_id CHAR(36) NOT NULL
        REFERENCES spring_session(primary_id) ON DELETE CASCADE,
    attribute_name     VARCHAR(200) NOT NULL,
    attribute_bytes    BYTEA NOT NULL,
    PRIMARY KEY (session_primary_id, attribute_name)
);
```

> 注意：PostgreSQL 会把未加引号的标识符转小写。Spring Session 的 SQL 使用未加引号的 `SPRING_SESSION`，最终访问小写表名；建表也用未加引号的小写名即可，保持一致。

## 3. 分阶段实施

### 阶段 0：环境与驱动

1. 申请/创建 GaussDB 实例、数据库、schema、账号。
2. 确认 JDBC 驱动和连接串：

```yaml
spring:
  datasource:
    driver-class-name: org.postgresql.Driver
    url: jdbc:postgresql://<host>:<port>/digital_book?currentSchema=digital_book
    username: ${BOOK_DB_USERNAME}
    password: ${BOOK_DB_PASSWORD}
```

3. 在 `book-java` 下测试连接：

```bash
mvn "-Dmaven.compiler.source=1.8" "-Dmaven.compiler.target=1.8" clean package -DskipTests
java -jar target/digital-book-service.war --spring.profiles.active=gauss
```

4. 确认 `pom.xml` 中驱动可用。如果现有 `huaweicloud-dws-jdbc` 不提供 `org.postgresql.Driver`，增加：

```xml
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <scope>runtime</scope>
</dependency>
```

### 阶段 1：表结构与触发器

1. 以当前 `book-mysql.sql` 为准，生成 `book-gauss.sql`。
2. 创建全部业务表和会话表。
3. 创建序列/identity 并设置起始值。
4. 创建触发器（当前 MySQL 脚本中有两个）：
   - 删除书籍前删除 `book_detail`
   - 删除借阅记录后 `book.stock + 1`

Gauss/PL-pgSQL 示例：

```sql
CREATE OR REPLACE FUNCTION delete_book_detail_func()
RETURNS TRIGGER AS $$
BEGIN
    DELETE FROM book_detail WHERE book_id = OLD.book_id;
    RETURN OLD;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER delete_book_trigger
BEFORE DELETE ON book
FOR EACH ROW EXECUTE PROCEDURE delete_book_detail_func();

CREATE OR REPLACE FUNCTION add_book_stock_func()
RETURNS TRIGGER AS $$
BEGIN
    UPDATE book SET stock = stock + 1 WHERE book_id = OLD.book_id;
    RETURN OLD;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER delete_borrow_info_trigger
AFTER DELETE ON borrow_info
FOR EACH ROW EXECUTE PROCEDURE add_book_stock_func();
```

> 如果使用 `ON DELETE CASCADE`，删除书籍的触发器可以省略；但两套脚本要统一，不要同时保留重复逻辑。

### 阶段 2：代码与 SQL 改造

#### 2.1 分页方言

`MybatisPlusConfig.java` 当前硬编码 `DbType.MYSQL`。两种做法：

- 如果只保留 Gauss：改为 `DbType.POSTGRE_SQL`
- 如果同时保留 MySQL / Gauss：按 profile 创建两个 `MybatisPlusInterceptor` Bean，或读取 `mybatis-plus.db-type` 配置

推荐后者，方便回滚。

#### 2.2 数据大屏 SQL

`DashboardMapper.xml` 是 MySQL 语法最集中的文件：

```sql
-- MySQL
select date_format(from_unixtime(borrow_time / 1000), '%Y-%m-%d') as `date`,
       count(*) as `count`
from borrow_info
where from_unixtime(borrow_time / 1000) >= date_sub(curdate(), interval 13 day)
group by date_format(from_unixtime(borrow_time / 1000), '%Y-%m-%d')
order by date_format(from_unixtime(borrow_time / 1000), '%Y-%m-%d')
```

改为：

```sql
select to_char(to_timestamp(borrow_time / 1000.0), 'YYYY-MM-DD') as "date",
       count(*) as "count"
from borrow_info
where to_timestamp(borrow_time / 1000.0) >= current_date - interval '13 day'
group by to_char(to_timestamp(borrow_time / 1000.0), 'YYYY-MM-DD')
order by to_char(to_timestamp(borrow_time / 1000.0), 'YYYY-MM-DD')
```

同时：

- 去掉所有反引号
- `curdate()` → `current_date`
- `date_sub(... interval 13 day)` → `current_date - interval '13 day'`
- `limit 8` 保留即可；不要用 `limit offset,count`
- `count`、`value` 等别名建议加双引号，避免关键字歧义

`DashboardServiceImpl` 的 Java 补零逻辑不用改，接口返回字段保持一致。

#### 2.3 其他 Mapper

| 文件 | 现状 | 改造 |
| --- | --- | --- |
| `BookMapper.xml` | `update book set stock=stock-1` | 可直接用 |
| `BorrowInfoMapper.xml` | `stock > 0` | Gauss 返回 boolean，MyBatis `Boolean` 映射需实测 |
| `UserMapper.xml` | 多表 join | 可直接用，注意大小写 |
| `UserLog` 相关 | MyBatis-Plus 查询 | 一般不用改 |

#### 2.4 备份/恢复功能

`BackupServiceImpl` 是 MySQL 专用实现，迁移时必须处理：

- `jdbc:mysql://` 正则不支持 `jdbc:postgresql://`
- `mysqldump` / `mysql` 命令不适用
- `--set-gtid-purged`、`--no-tablespaces` 等参数只适用于 MySQL
- `@@log_bin` 预检查只适用于 MySQL
- 恢复账号需要 Gauss 的权限

建议二选一：

**方案 A：抽象命令（推荐，保留功能）**

- 按 profile 选择备份工具：
  - MySQL：`mysqldump` / `mysql`
  - Gauss：`gs_dump` / `gsql`，或 `pg_dump` / `psql`
- URL 解析同时支持 `jdbc:mysql://` 和 `jdbc:postgresql://`
- 配置文件从 MySQL `[client]` 改为 Gauss 的连接参数/密码文件
- 恢复前预检查改为 Gauss 权限检查

**方案 B：高斯环境禁用应用内备份（省时间）**

- 在 `gauss` profile 下关闭备份/恢复页面或接口
- 使用 GaussDB/RDS 自带备份
- 文档里明确说明“应用内备份仅 MySQL 版本支持”

如果老师要求功能完整，选 A；如果只是演示数据库迁移，选 B 更稳。

建议停写窗口内操作，先备份 MySQL。

1. 从 MySQL 导出数据（CSV 或按表 SQL）：

   - `role_privilege`
   - `book`
   - `book_detail`

```sql
COPY u_user FROM '/data/u_user.csv' CSV HEADER;
-- ...
```

3. 重置序列：

```sql
SELECT setval('book_book_id_seq', (SELECT max(book_id) FROM book));
SELECT setval('u_user_user_id_seq', (SELECT max(user_id) FROM u_user));
SELECT setval('user_log_log_id_seq', (SELECT max(log_id) FROM user_log));
```

5. 图片文件不需要迁移进数据库，保持 `uploads` 目录和 `book_detail.image` 路径一致。

6. 校验：


## 4. 常见兼容性坑

| 问题 | 说明 |
| --- | --- |
| 自增主键 | `AUTO_INCREMENT` 不支持，改 `SERIAL`/identity；确认 MyBatis-Plus 能取回生成 ID |
| 布尔值 | MySQL `stock > 0` 返回 0/1，Gauss 返回 boolean，`BorrowInfoMapper` 要实测 |
| 大小写 | 未加引号会转小写；表名、字段名统一小写 |
| 反引号 | 全部删除或换双引号 |
| 日期函数 | `FROM_UNIXTIME`、`DATE_FORMAT`、`CURDATE`、`DATE_SUB` 全部替换 |
| 分页 | 不要用 `LIMIT offset,count`；用 `LIMIT count OFFSET offset` 或 MyBatis-Plus 方言 |
| `GROUP BY` | 严格模式要求所有非聚合列出现在 GROUP BY |
| 触发器 | 需要 PL/pgSQL；创建触发器可能需要较高权限 |
| 会话表 | `ATTRIBUTE_BYTES` 必须是 `BYTEA`；表名大小写要一致 |
| 备份 | `mysqldump` 不能用于 Gauss；需要 `gs_dump`/`pg_dump` 适配 |
| 旧脚本 | `book-gauss.sql`、`database.sql` 是旧版，不能直接当当前 schema 用 |
| 时区 | `borrow_time/deadline` 是毫秒 bigint，展示时注意时区；`TIMESTAMP` 不要和 `TIMESTAMPTZ` 混用 |
