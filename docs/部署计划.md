# 部署计划（ECS 主备 + 自动切换）

> 适用版本：当前 MySQL 8.0 版本（高斯数据库迁移见 `docs/高斯数据库改造计划.md`）
> 目标：2 台 ECS 一主一备，Keepalived VIP 自动切换，业务不中断。
> 读者：负责服务器部署的同学。

## 1. 目标架构

```
用户浏览器
    │
 域名 / 公网入口
    │
 VIP（虚拟 IP，例如 192.168.1.100）
    ├── ECS-1（主）：Nginx + book-app :8088
    └── ECS-2（备）：Nginx + book-app :8088
              │
        MySQL 8.0（RDS 主备版优先）
              │
        NAS / SFS 共享目录
        ├── uploads  （封面图片）
        └── backup   （数据库备份）
```

**关键点**

- 两台 ECS 部署同一套前端和后端，只有主服务器持有 VIP。
- Keepalived 每 2 秒检查本机 Nginx 和后端，连续失败 3 次触发 VIP 漂移。
- 登录会话存放在 MySQL 的 `SPRING_SESSION` 表，两台应用共享，切换后不需要重新登录。
- 图片和备份必须放共享 NAS，否则切到备机后图片 404、备份列表不一致。
- 数据库建议用 RDS 主备版；如果数据库在单台 ECS 上，数据库仍是单点，答辩时不要声称数据库也高可用。

## 2. 资源清单

| 资源 | 数量 | 说明 |
| --- | --- | --- |
| ECS | 2 台 | 建议 4 核 8G，同一 VPC/子网；Ubuntu 22.04 或 CentOS 7.9 |
| 虚拟 IP | 1 个 | 与两台 ECS 同网段，如 `192.168.1.100` |
| 公网 IP / 域名 | 按需 | 云平台支持 EIP 绑定 VIP 最好；否则用 ELB 做公网入口 |
| 安全组 | 2 个 | ECS 安全组、数据库安全组 |
| MySQL | 1 套 | 推荐 RDS MySQL 8.0 主备版；最低可用独立 ECS 自建 |
| NAS / SFS | 1 个 | 两台 ECS 同时挂载 |
| JDK | 2 套 | JDK 11（项目按 Java 8 编译，JDK 11 运行稳定） |

**端口规划**

| 端口 | 开放范围 | 用途 |
| --- | --- | --- |
| 80 / 443 | 公网 | Nginx 前端与 API 入口 |
| 8088 | 仅本机/内网 | Spring Boot 后端 |
| 3306 | 仅 ECS 到数据库 | MySQL |
| 112（VRRP） | 两台 ECS 之间 | Keepalived |
| 22 | 运维 IP | SSH |

两台 ECS 都确认：

- [ ] 时间同步正常（`timedatectl`）
- [ ] 两台机器在同一子网，内网互通
- [ ] 安全组放行 80/443、8088（内网）、VRRP 112（ECS 之间）
- [ ] NAS 已创建并可在两台机器挂载

## 5. 两台 ECS 初始化

以下以 Ubuntu 为例，CentOS 将 `apt` 换成 `yum`。

```bash
# 创建运行用户和目录
sudo useradd -r -m -d /opt/book book
sudo mkdir -p /opt/book /var/www/book /data/book/uploads /data/book/backup
sudo chown -R book:book /opt/book /var/www/book /data/book

# 安装依赖
sudo apt update
sudo apt install -y openjdk-11-jdk nginx keepalived mysql-client curl

# 防火墙
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```

> 如果使用 RDS，MySQL 客户端用于应用内备份功能；如果不用应用内备份，可以只装 `curl`。

## 6. 数据库准备

### 6.1 建库建账号

在 RDS 或数据库 ECS 上执行：

```sql
CREATE DATABASE digital_book DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER 'book_app'@'%' IDENTIFIED BY '强密码';
GRANT ALL PRIVILEGES ON digital_book.* TO 'book_app'@'%';
FLUSH PRIVILEGES;
```

### 6.2 初始化表结构

> `book-mysql.sql` 会 `DROP TABLE`，只能在**空库**执行，不要对已有数据执行。

```bash
mysql -h <数据库地址> -u book_app -p digital_book < book-java/book-mysql.sql
```

验证 11 张表：

```sql
SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='digital_book';
-- 11
```

### 6.3 应用环境变量

两台 ECS 使用同一个数据库。创建 `/etc/book/book.env`，权限 600：

```bash
SPRING_PROFILES_ACTIVE=mysql
BOOK_DB_URL=jdbc:mysql://<数据库内网地址>:3306/digital_book?useSSL=FALSE&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
BOOK_DB_USERNAME=book_app
BOOK_DB_PASSWORD=强密码
BOOK_BACKUP_RESTORE_USER=root
BOOK_BACKUP_RESTORE_PASSWORD=恢复账号密码
```

> 应用内恢复如果遇到 binlog + 触发器权限问题，需要配置 `BOOK_BACKUP_RESTORE_USER/PASSWORD`；RDS 上如果没有 SUPER 权限，建议直接用 RDS 自动备份，不演示应用内恢复。

## 7. 构建

### 7.1 后端

```bash
cd book-java
export JAVA_HOME=/usr/lib/jvm/java-11-openjdk-amd64
mvn "-Dmaven.compiler.source=1.8" "-Dmaven.compiler.target=1.8" clean package -DskipTests
```

产物复制到两台 ECS：

```bash
scp target/digital-book-service.war book@<ECS-IP>:/opt/book/
```

### 7.2 前端

```bash
cd book-vue
npm install
NODE_OPTIONS=--openssl-legacy-provider npm run build
```

生产环境用同源访问，把 `public/api.config.json` 改成：

```json
{ "BASE_URL": "" }
```

然后重新构建。将 `dist/` 复制到两台 ECS 的 `/var/www/book/dist`。

## 8. 后端 systemd

创建 `/etc/systemd/system/book-app.service`：

```ini
[Unit]
Description=Digital Book Service
After=network.target

[Service]
User=book
Group=book
WorkingDirectory=/opt/book
EnvironmentFile=/etc/book/book.env
ExecStart=/usr/bin/java \
  -Dbook.upload.dir=/data/book/uploads \
  -Dbook.backup.dir=/data/book/backup \
  -jar /opt/book/digital-book-service.war
Restart=always
RestartSec=3
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now book-app
sudo systemctl status book-app --no-pager
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8088/book/user/login/check
# 200
```

## 9. Nginx

创建 `/etc/nginx/conf.d/book.conf`：

```nginx
server {
    listen 80;
    server_name _;

    root /var/www/book/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location ~ ^/(book|detail|borrow|system|dashboard)/ {
        proxy_pass http://127.0.0.1:8088;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

检查并加载：

```bash
sudo nginx -t
sudo systemctl reload nginx
curl -I http://127.0.0.1/
```

## 10. 共享存储（必须）

在 NAS 控制台创建文件系统，两台 ECS 挂载到 `/data/book`：

```bash
sudo mount -t nfs <NAS地址>:/book /data/book
sudo chown -R book:book /data/book
sudo -u book touch /data/book/uploads/.write-test
```

两台都执行，确认：

```bash
ls -l /data/book/uploads/.write-test
```

> 没有 NAS 时，应用主备切换后会出现图片 404、备份列表不一致；不要省略这一步。

## 11. Keepalived

### 11.1 健康检查脚本

两台都创建 `/etc/keepalived/check_book.sh`：

```bash
#!/bin/bash
systemctl is-active --quiet nginx || exit 1
curl -fsS --max-time 2 http://127.0.0.1:8088/book/user/login/check >/dev/null || exit 1
exit 0
```

```bash
sudo chmod +x /etc/keepalived/check_book.sh
```

### 11.2 主服务器配置

`/etc/keepalived/keepalived.conf`：

```conf
vrrp_script chk_book {
    script "/etc/keepalived/check_book.sh"
    interval 2
    weight -30
    fall 3
    rise 2
}

vrrp_instance VI_BOOK {
    state MASTER
    interface eth0
    virtual_router_id 51
    priority 100
    advert_int 1

    unicast_src_ip <ECS-1内网IP>
    unicast_peer {
        <ECS-2内网IP>
    }

    virtual_ipaddress {
        <VIP>/24
    }

    track_script {
        chk_book
    }
}
```

### 11.3 备服务器配置

只改三处：

```conf
state BACKUP
priority 90
unicast_src_ip <ECS-2内网IP>
```

`unicast_peer` 写主服务器 IP。

> 如果希望主服务器恢复后不抢回 VIP，加 `nopreempt`；演示前确认你要展示“自动回切”还是“留在备机”。

### 11.4 启动与检查

两台：

```bash
sudo systemctl enable --now keepalived
sudo systemctl status keepalived --no-pager
sudo journalctl -u keepalived -n 30 --no-pager
```

主服务器：

```bash
ip addr | grep <VIP>
```

只有主服务器能看到 VIP。

## 12. 启动顺序与验收

1. 数据库就绪
2. 两台 ECS 启动 `book-app`
3. 两台 ECS 启动 `nginx`
4. 主服务器启动 `keepalived`，备服务器启动 `keepalived`

验收：

```bash
# 两台分别检查
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8088/book/user/login/check
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/

# 通过 VIP 访问
curl -I http://<VIP>/
```

浏览器打开 VIP，登录 `admin / 123456`，进入书籍列表并搜索一次。

## 13. 自动切换测试（演示用）

### 13.1 应用故障

主服务器：

```bash
sudo systemctl stop book-app
```

等待约 6 秒，备服务器：

```bash
ip addr | grep <VIP>
sudo journalctl -u keepalived -n 30 --no-pager
```

预期：VIP 出现在备服务器，Keepalived 日志出现 `Entering BACKUP STATE` / `Entering MASTER STATE`。

浏览器刷新 VIP 地址：

- 页面正常
- 仍是 admin 登录状态
- 可以继续搜索/借阅

恢复主服务器：

```bash
sudo systemctl start book-app
```

### 13.2 Nginx 故障

主服务器：

```bash
sudo systemctl stop nginx
```

健康检查脚本会返回失败，VIP 漂移；恢复：

```bash
sudo systemctl start nginx
```

### 13.3 数据库主备（可选）

如果使用 RDS 主备版：

1. 在控制台执行“主备切换”
2. 观察应用接口短暂失败后恢复
3. 浏览器刷新，数据正常

如果数据库是单台 ECS，不要演示数据库故障，直接说明数据库是独立节点。

## 14. 故障排查

| 现象 | 排查 |
| --- | --- |
| VIP 不漂移 | 检查 keepalived 日志、防火墙 112、`unicast_peer`、priority、interface |
| 浏览器 502 | 检查 `book-app`、Nginx 代理、8088 端口 |
| 切换后要重新登录 | 检查 `SPRING_SESSION` 是否在共享 MySQL，两个应用是否连同一个库 |
| 图片 404 | 检查 NAS 是否两台都挂载、`book.upload.dir` 是否一致 |
| 备份列表不一致 | 检查 `book.backup.dir` 是否指向 NAS |
| 数据库连接失败 | 检查 RDS 白名单、环境变量、账号权限 |
| 恢复失败 | 检查恢复账号权限、binlog 触发器权限；优先用 RDS 备份 |

## 15. 回滚方案

- 停止两台 `keepalived`，直接访问主 ECS 的 IP 或 Nginx 端口。
- 保留 MySQL 原库和备份文件，不删除。
- 应用回滚到上一版 war 和 dist。
- 数据库恢复使用 RDS 备份或应用内 `before-restore` 安全备份。

## 18. 重要提醒

- 不要在两台机器同时手动启动同一个 VIP。
- 不要把 MySQL root 密码写进仓库；使用 `/etc/book/book.env` 或云密钥。
- `book-mysql.sql` 会删表，禁止在已有数据的环境重复执行。
- 上线前先做一次完整演练，记录 VIP 漂移所需时间。
- 如果云平台限制 VRRP，改用 ELB 健康检查方案，答辩时说明这是云上等价实现。
